# StarPie 多风格美术与用户自定义设计

日期：2026-10-05

状态：用户已批准实施（2026-10-05）。
源码基线：Star-Pie/StarPie，main，de9dca9。

## 目标与默认范围

将 StarPie 的设置控制台、宿主弹窗、一级和二级轮盘统一接入可编辑的美术主题。用户可以一键切换完整风格，复制预设后调色、调节视觉参数、保存自己的主题，并单独导入或导出主题文件。

本次默认将“自定义”解释为：通过界面编辑颜色、字体、圆角、描边、阴影、透明度与装饰强度，而不是要求用户编写代码。已有图标、中心图片、轮盘尺寸、动作配置和每扇区覆盖功能继续使用原入口。

## 已确认的项目基础

- 原生 .NET 8 WPF 桌面程序，主项目在 `WinPieGestures/`。
- `AppThemeManager.cs` 注入设置窗口与弹窗使用的语义画刷资源，当前主题主要对应浅色、深色和钛金灰。
- `BaseStyleRenderer.cs` 与三个具体轮盘渲染器处理配色、描边、光晕与装饰；轮盘形态另有配置。
- `CustomColorPreset.cs` 当前保存五种轮盘颜色，不能表达完整的应用美术风格。
- 设置页已有实时轮盘预览、自定义配色保存与配置导入导出。
- `ConfigManager.ConfigurationRevision` 已提供视觉配置更新标记，可用于刷新长期复用的轮盘窗口。
- 当前环境未在命令路径中找到 .NET SDK；实施前需检查已安装位置，或准备构建环境。

## 方案比较

| 方案 | 用户体验 | 工作与限制 |
| --- | --- | --- |
| 可编辑的统一主题配置（推荐） | 一键切换完整风格，设置页、弹窗和轮盘保持一致，普通用户可直接编辑 | 需要统一资源解析和增加主题工作室；继续使用原生 WPF |
| 扩充现有配色预设 | 能迅速增加颜色选择 | 设置窗口与轮盘仍分离，字体、材质和装饰缺少统一表达 |
| 开放任意 XAML 模板或主题插件 | 作者可以重写整个界面 | 模板兼容、性能、升级和错误隔离成本较高，不适合作为首版 |

## 建议内置风格

每套风格同时定义界面和轮盘，差异包含颜色、线条、圆角、字重、阴影及装饰。保持扇区方向与动作位置；默认不改变轮盘尺寸和命中区域。

| 风格 | 色彩方向 | 视觉语言 |
| --- | --- | --- |
| 纸感极简 Paper | 暖白 `#F5F1E8`、墨色 `#252820`、砖红 `#B54735` | 大留白、细描边、低阴影、小圆角、简洁线性图标 |
| 曜石科技 Obsidian | 炭黑 `#11171B`、青绿 `#63D9CA`、浅灰 `#E8F0EF` | 清晰仪表线、克制高亮、角标与轨道装饰 |
| 森林柔和 Grove | 浅鼠尾草 `#EEF3EA`、深绿 `#263B2D`、苔绿 `#54764D` | 柔和圆角、哑光卡片、低强度投影、宽松间距 |
| 冰川玻璃 Glacier | 冰白 `#EAF4F8`、海蓝 `#176B8A`、深蓝 `#163745` | 半透明轮盘、精细亮边与柔和层次，控制台保证文字清晰 |
| 复古像素 Pixel | 米黄 `#F2E9CD`、近黑 `#292C32`、橙红 `#B74327` | 方角、阶梯装饰、粗描边、硬投影、等宽数字标签 |

中文正文使用适合阅读的本机字体回退。像素风通过边框、投影和装饰实现，不强制将中文正文像素化。主题色值是设计起点，实施时以实际控件状态和对比度校验调整。

## 主题工作室

在现有“外观与形态”页顶部增加主题工作室，保留右侧实时轮盘预览。

1. 顶部展示主题卡片：缩略轮盘、风格名、色板、内置或自定义标记、当前选中状态。
2. 点击“应用”立即更新设置页、宿主弹窗和轮盘；切换无需重启。
3. 点击“复制并编辑”创建独立草稿，内置主题保持可恢复。
4. 编辑区提供基础与进阶选项：强调色、背景、文字、边框、圆角、描边、阴影、轮盘透明度、字体和装饰强度。
5. 草稿编辑即时更新界面控件样例与轮盘预览。保存后才替换已保存主题；取消丢弃草稿并恢复当前主题。
6. 支持新建、重命名、删除、重置、导入和导出。删除正在使用的自定义主题时回到内置默认主题。
7. 提供“轮盘跟随整体风格”选项。关闭后保持原有一级和二级轮盘独立配色，继续使用旧编辑器。

换主题只改变视觉属性。轮盘半径、扇区数量、动作、触发距离、程序方案和声音设置不属于主题文件。用户原有每扇区字体、图标、文字颜色覆盖继续具有最高优先级。

## 数据与模块

新增小而独立的主题模块，避免继续扩张设置窗口的主代码文件：

- `ArtStyleProfile`：有稳定 ID、名称、结构版本、界面视觉参数与轮盘视觉参数的纯数据模型。
- `ArtStyleCatalog`：提供内置主题和用户主题；内置主题只读，复制时产生新的用户 ID。
- `ArtStyleResolver`：解析选中主题和用户覆盖，生成校验后的有效视觉参数；不进行文件读写。
- `ArtStyleService`：应用、保存、删除、导入导出与变更通知的统一入口。
- `ThemeStudio`：主题卡片与草稿编辑的专用 WPF 控件，设置页仅负责接入和联动。

`AppConfig` 增加选中主题 ID、轮盘是否跟随以及用户主题列表。主题颜色使用具名字段，避免继续增加长位置参数列表。复用已有语义资源名，并补充圆角、字体、描边与阴影资源。

`AppThemeManager` 读取解析后的界面资源；轮盘渲染器读取同一主题的轮盘资源。主题切换在 UI 线程更新已打开的宿主窗口，随后标记配置修订、刷新预览并保存配置。新打开窗口直接读取当前主题。变更通知使用可释放或弱引用订阅，避免阻碍设置窗口延迟释放。

原有“跟随系统 / 浅色 / 深色 / 钛金灰”保留为基础主题入口。选择完整美术主题时，由主题的显式明暗属性决定标题栏、品牌标志和托盘；再次选择基础主题入口时清空选中的美术主题 ID，回到原有外观模式。这两个入口互斥，界面同步显示当前选择，避免将所有非 `Light` 名称都判断为深色。用户主题的明暗属性默认继承被复制的主题，也可在进阶设置中调整。

## 旧配置兼容与错误处理

- 旧配置缺少新字段时进入原有外观模式，不自动覆盖已有自定义配色或动作。
- 现有 `AppTheme`、`Theme`、`UiStyle`、`Shape`、`CustomColorPresets` 和二级独立配置保留读取能力。
- 完整配置导入导出包含用户主题；单独主题导入导出只包含美术参数，不包含动作、插件或触发配置。
- 导入使用有结构版本的 JSON。先在内存中校验整份文件，再添加主题，失败时保留当前配置并说明问题字段。
- 颜色必须能解析；数值必须有限且在界面允许范围内；不支持的结构版本明确拒绝。缺少可选字段使用对应内置默认值。
- ID 冲突时为导入副本生成新 ID，避免覆盖已有主题。主题名称使用文本显示，不作为文件路径。
- 找不到已选主题时回到内置默认主题并提示；不删除用户原主题数据。
- 首版主题文件是纯数据，不装载 XAML、程序集、脚本或外部字体。已有本地图标和中心图片继续使用项目现有资源机制。

## 性能与可读性

继续使用原生 WPF，不增加大型 UI 依赖。主题在应用或配置变化时解析，鼠标钩子和扇区高亮路径不读文件。新画刷、几何和阴影按项目要求冻结并缓存。透明度与装饰参数有范围上限；玻璃效果采用已有轻量绘制能力。

主题编辑器检查正文和背景的对比度并显示提示；内置主题的普通正文达到 4.5:1。高亮、悬停、禁用和键盘焦点状态都有对应颜色，不能只验证静态页面。

## 验收与交付

1. 五套风格在设置页、代表性宿主弹窗和轮盘上形成清楚的视觉差异。
2. 一键应用后即时联动，下一次轮盘呼出使用新风格。
3. 复制、编辑、保存、重启后主题仍在；取消编辑恢复原主题。
4. 单独主题文件和完整配置分别完成导入导出往返。
5. 旧版配色、自定义预设、二级独立配置和每扇区覆盖保持有效。
6. 非法颜色、越界数值、结构版本错误和重复 ID 不破坏当前主题。
7. 验证多次切换和关闭设置窗口后事件订阅与窗口可释放。
8. 新界面词条接入项目已有四种语言。
9. Release 构建零错误，运行适用的无界面自检与静态护栏；完整 GUI 回归按项目要求由用户手动运行。
10. 按项目交付规范更新版本与变更记录，产出轻量版和独立版归档，附主题文件格式说明。
