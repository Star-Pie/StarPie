# 宏输入与 Alt 干扰修复

## 本轮范围与基线

- 用户已要求实施合并后的 P1：宿主额外修饰键输入及宏 Alt→A→E 菜单按键序列。其他左键、0ms、自启动、音效和层命名任务继续保留，不混入本候选。
- 宿主基线 `2db0a81`，官方插件基线 `775553c`；使用两边已有隔离工作树，分支均为 `codex/macro-alt-input-repair`。
- 宿主既有未跟踪诊断文件与优先级清单保留；插件开始时干净。不改日常数据、SDK、版本号、系统任务或公开发行包。
- 允许宿主修改 `ActionExecutor.cs`、`GestureController.cs`、输入失败提示的 `I18n.cs`、新增 `scratch/macro-input-tests/`、加强既有 `scratch/input-panel-tests/` 与 `scratch/test_wheel_focus/` 及本说明、Windows 输入规范；插件允许宏编辑器/词条、宏测试与对应说明，不改其他插件。

## 实施与验证

1. 加入内部输入记录切缝，先以未修复行为构建明确的观测候选，证明单 Alt 和轮盘正常收尾会生成多余输入。所有测试输入发送、键状态和扫描码映射均替换为假服务，不启动产品窗口、钩子或真实插件动作。
2. 轮盘会话不得全局释放并非该会话按下的修饰键；按键动作只收尾本次成功按下而尚未释放的键，不重复正常释放，不在动作结束后异步补发。
3. 单步与多步热键共用同一按键执行路径，保留扫描码、扩展键、PrintScreen 原子包、明确的步间隔及私有输入日志规则。拒绝发送失败，并覆盖部分成功、异常和已有物理修饰键。
4. 保留 TEXT 的 Unicode 文本语义；编辑器清楚提示菜单操作使用按键步骤。宏测试确认 Alt、A、E 各一次，不能把文本 AE 的成功输出当作菜单按键验收。
5. 修复候选按项目约定在新的时间戳 Release 目录构建，验证实际 DLL 哈希并运行专项与邻近回归。冻结后由独立原生 GPT 审查；DeepSeek/MAX 提供给定源码材料评议，不将其意见当作独立实机证据。
6. 人工复验空动作/取消无菜单闪动、文本选区、宏菜单操作、左右修饰键、Win/截图组合键及定格/普通轮盘。EPLAN、真实权限/IME 与设备行为仍由用户验收。

独立审查的两项补充均先建立前一候选失败证据再修复：宿主所有热键/文字/单键输入共用同步门，避免后台插件服务绕过动作队列交错；借用键在主键发送前重新检查。私有面板的执行失败保留脱敏日志并传回队列消费者，不再误报成功。`GetAsyncKeyState` 不是物理来源证明，真实外部输入在最后状态检查后的变化仍需实机评估。

本轮不提交、推送、合并、改标签、打包或发布。确认是输入副作用路径并不证明已经复现反馈机器上的全部闪动现象。
