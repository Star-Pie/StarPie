# 小键盘1827验收修复与可视化配置

用户报告呼出后闪现消失，且配置界面缺少直观预览／拖拽。1827人工门禁标记为未通过，原候选保留，不覆盖其测试数据或已运行文件。宿主分支 `codex/restart-update-reliability` 基准773e8c8加已有未提交改动；插件分支 `codex/temporary-keyboard` 基准c1afcee加已有小键盘。先修小键盘，五级轮盘顺延。

## 范围

宿主：PluginInputPanelService、新的目标事件复核辅助类、PinnedWheelMonitor的时间戳回调重载、PluginActionBindingDialog、I18n及隔离测试／文档。原轮盘回调继续走无参数包装，不改变其取消规则。插件：KeyboardController、KeyboardWindow／共享轻量样式、KeyboardSchemeEditor／纯编辑状态、四语文案、对应测试和局部设计上下文。相对1827无SDK接口／版本变更，无配置格式迁移，不改启动／更新逻辑、其他插件或用户数据。

## 可检验假设

原PinnedWheelMonitor根据WinEvent的hwnd不同就取消，未保留事件时间。新路径只忽略早于输入会话的旧通知；本会话期间产生的切换／目标销毁通知立即取消队列，即使通知送达时已回到原应用。窗口在监控前先创建句柄并应用NOACTIVATE样式，执行每项输入时仍检查真实窗口／PID。曾试用“回焦就保留”的方案，独立复核发现会放过真实短暂切换，已撤回。新增关闭原因日志只含枚举、不含输入或窗口标题。该假设需要新候选实机验证，不宣称已证明是用户机器的唯一根因。

WinEvent为异步通知：真实切走又切回、通知尚未到达时，已消费的输入不能被时间戳追溯撤销；同一毫秒边界也不证明事件严格先后。自动测试只验证给定事件及替身队列，不代替真实焦点／输入验证。

另有日志证据：无效目标时Open抛异常，但既有DispatcherFacade会吞回调异常，动作仍报成功。插件控制器须将UI操作结果带回动作调用者，不能修改全局调度器语义。

## 配置交互

左侧方案与已用动作，中央实际键盘预览，右侧当前按键属性。点击选择、双击选择插件动作、拖拽按键交换／拖已用动作复制、撤销／重做；支持不拖拽的选择与修改方式。数字／字母／功能／全键盘布局可只读预览，自定义3×4画布可编辑。预览不打开输入会话，不执行动作。

空动作选择器明确说明需要其他已安装且启用的插件；普通展示不自动安装／启用。宿主表单与主题复用，保存仍使用原私有文件与显式损坏恢复。编辑历史按产品内存预算有界；不是模型调用或修复轮次配额。

## 分工与门禁

DeepSeek/MAX只实施纯编辑状态和独立测试，主代理负责焦点边界、WPF、文案和整合；最终由未实施者独立源码复核。最多两位工作者，不递归。先固定输入替身及路径，所有自动测试禁止Show、真实输入、插件动作、系统修改；1824隔离事故作为既有反例保留，不再绕过输入替身运行。

新候选使用新的时间戳Release目录，绑定DLL和插件哈希。验证目标事件的过期／真实变化、调度错误传播、编辑深克隆／拖拽／撤销／保存、窗口模板／布局及既有输入会话门禁。真实不抢焦点、连续输入、拖拽手感、空状态、主题／DPI由用户重新验收，未通过不合并。没有本阶段提交／发布授权。
